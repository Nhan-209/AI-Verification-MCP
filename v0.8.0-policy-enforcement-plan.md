> Evolution from Heuristic Diagnostics to a Formal Policy Enforcement & Claim-Level Grounding Layer for Autonomous AI Agents.

## 🎯 Executive Summary & Objectives

Based on the comprehensive v0.7.0 re-review (7.8/10 rating), the remaining architectural barriers separating this project from an industrial-grade verifier have shifted from obvious bugs to **trust-model and policy semantics**.

Version **v0.8.0** completes the transition described in the system roadmap:
\text{Heuristics + Renormalized Scores} \xrightarrow{\quad\text{v0.8.0}\quad} \text{Claim-Level Evidence Graph + Provenance + Hard Policy Invariants}

## 🏗️ The 5 Core Engineering Deliverables

### Deliverable 1: Decouple Diagnostic Score from Governance Decision (P0)
- **Problem**: Unified audit computes $\text{policy\_score} = \sum (s_i \cdot w_i) / \sum w_i$ only over provided pillars. A payload providing only an eloquent draft_response activates confidence, research, and foresight, potentially yielding an ALLOW score while completely bypassing contract and DAG verification.
- **Solution**:
  1. policy_score is strictly downgraded to a **diagnostic health index** (.0 - 100.0$).
  2. The decision (ALLOW, WARN, BLOCK, INSUFFICIENT_EVIDENCE) is governed 100% by a **Deterministic Policy Engine**:
     - Hard Invariants override any numerical score.
     - An ALLOW verdict is mathematically impossible unless all mandatory evidence requirements for the governance mode are explicitly satisfied.

### Deliverable 2: Mandatory Evidence Matrix (P0)
Define explicit contract requirements per governance profile:

| Governance Mode | Mandatory Evidence Required | Failure Outcome if Missing |
|---|---|---|
| **quick** | At least one input signal (draft_response, user_requirements, or code_snippet) | INSUFFICIENT_EVIDENCE |
| **standard** | 1. User requirements or task plan<br>2. Execution trace or draft response<br>3. Grounded citations for all factual claims | Missing contract $\rightarrow$ INSUFFICIENT_EVIDENCE<br>Unverified claims $\rightarrow$ BLOCK |
| **deep** | 1. Formal requirements ({\text{user}} \ne \emptyset$)<br>2. Plan DAG ({\text{plan}} \ne \emptyset$)<br>3. 100% Execution coverage ( = 1.0$)<br>4. Zero unverified claims | Any missing pillar $\rightarrow$ BLOCK<br>Code violation $\rightarrow$ BLOCK |

### Deliverable 3: Claim-Level Verification & Mixed Evidence Fix (P0)
- **Problem**: has_research_deficit currently triggers only when $\text{factual\_claims} \ge 1 \land \text{total\_verified} == 0$. If an agent makes Claim A (citing docs.rs) and Claim B (fake citation), $\text{total\_verified} = 1$, letting Claim B bypass detection.
- **Solution**:
  - Enforce the **Universal Grounding Axiom**:
    \forall c \in \text{ClaimAnalyses}, \quad c.\text{is\_verified} == \text{true}
  - If *any* material factual claim is unverified, trigger CLAIM_UNGROUNDED (Critical) and set has_research_deficit = true. A valid source for Claim A cannot launder Claim B.

### Deliverable 4: Curated Known RFC Registry & Provenance Grounding (P1)
- **Problem**: Syntactic check  \le \text{RFC} \le 9999$ permits imaginary RFC numbers (e.g., RFC 9999). Bare mentions of standards organizations ("ISO", "IEEE") or text saying "tests passed" are currently treated as evidence.
- **Solution**:
  1. Curate KNOWN_RFC_REGISTRY containing established IETF standards (RFC 791, 793, 2119, 2616, 3986, 5246, 6749, 7230, 7231, 7519, 7540, 8259, 8446, 9110, 9113, etc.). Numbers outside the registry are categorized as uncataloged/unverified.
  2. Require structured standards references (e.g., "IEEE 754", "ISO/IEC 27001") rather than bare organization mentions.

### Deliverable 5: Adversarial Suite Expansion & Positioning Alignment (P1)
- **Adversarial Tests**:
  - 	est_partial_input_score_gaming_rejected: Flowery draft response without requirements/tasks cannot receive ALLOW.
  - 	est_mixed_evidence_partial_spoofing_rejected: Mixed valid and fake citations in the same response triggers BLOCK.
- **Positioning Alignment in README / Docs**:
  - Formal title: **Deterministic Evidence & Policy Enforcement Layer for AI Agents**.
  - Epistemic Guarantee:
    \text{ALLOW} \equiv \text{No policy violation detected under declared evidence policy}
    \text{ALLOW} \not\equiv \text{Empirical proof that the AI is omniscient or infallible}
